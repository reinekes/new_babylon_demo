# Приёмка исторической ветви

Изолированные страницы используют настоящие модули игры. Они не импортируют `app.js`, не читают и не записывают города. Запустить обычный статический сервер из корня репозитория; открыть:

- `tools/history-check/index.html` — обе ветви, отдельные стартовый и обычный дома, три яруса зиккурата, святилище и ворота. Подпись берётся из `buildingPresentation`, материалы — из созданных мешей; «Протокол» содержит фактический состав. PASS относится только к неизменности входных данных.
- `tools/history-check/2d.html` — настоящие 2D-силуэты и подписи обеих ветвей. Прежний 2D-стартовый дом уже использовал общий двор; галерея не подменяет его 3D-ульем.
- `tools/history-check/transport.html` — модели каравана/лодки; «Движение» включает искусственное перемещение для проверки походки, повторное нажатие ставит на паузу. «Снять показания» фиксирует фазы, позиции, запасы и неизменность входов каждого обновления. Это проверка представления; настоящие маршруты/доставка проверяются отдельно в большом городе и тестах.

Исторические границы и результаты: [отчёт](../../docs/HISTORY_ACCEPTANCE_2026-11-05.md). Новые шумерские формы — игровые интерпретации, не точные реконструкции; старые модели сохранены для совместимости. Стенд не измеряет FPS.

## Каналы и полный цикл поля

`tools/history-check/farming.html` создаёт настоящую новую партию взрослого бога/seed137:12жителей,5стартовых домов и обычные начальные запасы. Нажимать по порядку: «Заложить канал» → «До груза» → «Сохранить и загрузить» → «До готовности» → «Следующий участок» → «Построить поле» → «До посева» → «До роста» → «До жатвы» → «До обмолота» → «Сохранить и загрузить». Жители сами несут материалы/семена, строят, сеют, режут и обмолачивают; два работника закрепляются обычной командой. События пропускаются через resolveEvent и записываются. Ни готовность строек, ни crop/ресурсы напрямую не присваиваются.

Стенд пошаговый:20настоящих шагов по0.1с за кадр, остановка на реальном условии. Дневной вид помогает читать поле, распорядок жителей не меняется. Это не замер FPS. Сохранение хранится только в памяти страницы. В протоколе отдельно byteExact, equal и equivalent: допускается≤1e-9 только в локальных building.stock по материалам, все остальные поля (включая грузы, людей, посев и часы) требуют точного совпадения. Фактически замечено7.1e-15 в stock.food при штатном согласовании запасов; разница сохранена, не названа побайтовым равенством. Проверки повреждённого груза/личности/урожая это допущение не проходят.

Транспортный стенд теперь показывает фактические riverCargo-меши и stockSignature. Выбор груза — только вход изолированной проверки: исходные4вида,15видов,пусто,один камень. Одна условная упаковка обозначает вид груза; точные количества живут в stock. В настоящем городе груз проверен отдельно в реальном речном визите4×.
