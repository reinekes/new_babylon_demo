Это снабжённый нагрузочный стенд, не доказательство самостоятельного развития города из основателей. Отдельный путь C01 без тестовых ресурсов записан в `benchmarks/2026-11-05-c01-founders.json`.

Ранние прогоныv1–v3 не входят в эту таблицу: неснабжённый речной город голодал, похороны сбросили скорость до1×. Такой результат исключён из приёмки4×. Старый публичный стенд без рынка отличается составом/режимом/снабжением; сравнение его31.16FPS с нынешними~25 не доказывает регрессию конкретной правки. Для атрибуции нужен одинаковый сценарий на сравниваемых версиях.

Не запускать тяжёлые проверки одновременно с замером.

## Контроль исторического профиля

На том же текущем коде проведён дополнительный land/overview/80с прогон с `history=legacy`:26.36FPS,p9550.1мс,max633.4мс,229 жителей,4×,валидный save,все торговые грузы завершены. Начальные состояния обоих профилей отдельно сопоставлены целиком после encode: для land и river они идентичны за исключением scenario. Подробный контроль: [JSON](benchmarks/2026-11-05-sumer-trade-legacy-control.json). Строгий land/overview ранее дал24.98FPS. Оба ниже30; один прогон каждого не отделяет небольшой эффект оформления от разброса. Это сравнение профилей на текущем коде, не сравнение текущей версии с публичной.

Стенд теперь допускает `history=legacy` и по умолчанию сохраняет strict; добавлен счётчик количества/суммы/max времени каждого CPU-слоя, сбрасываемый перед каждым измерением. Нужен новый прогон с этим счётчиком: старые JSON не содержат средних значений, их нельзя восстановить из одних пиков>35мс.
