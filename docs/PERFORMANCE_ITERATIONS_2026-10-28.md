# Итеративное ускорение 3D · 28 октября 2026

> Исполнение: небольшие последовательные изменения, проверка и замер после каждого. Проверяющие работают независимо; тяжёлые тесты не идут одновременно с FPS-замерами.

**Цель:** ускорить большой город без изменения экономики, внешности жителей и количества растительности.

**Архитектура:** первая итерация кэширует неизменную внешность на экземпляре жителя; вторая заменяет отдельные статические объекты травы/тростника пакетами матриц Babylon; третья сохраняет готовую береговую землю поля между стадиями посева/урожая. Никаких новых зависимостей или изменений формата сохранений.

**Статус на 02.11.2026:** три изменения реализованы в отдельной рабочей копии, 1230/1230 тестов и 20/20 старых сохранений проходят. Снижение задержек полей подтверждено повторным CPU-замером. Критерий ≥30 FPS, визуальная приёмка и публикация **ещё не выполнены**.

**Стек:** JavaScript ES modules, Babylon.js 9.31.0, node:test, настоящие GLB и браузерный стенд.

**Основание:** пользователь одобрил продолжение [плана ускорения](PERFORMANCE_3D_AUDIT_2026-10-28.md). Выпуск до изменений: `8577090a8a175fe210ad03cc37c750947dda6a3a`.

**Уточнение пользователя:** продолжать, пока скорость не станет хорошей. Рабочий критерий — устойчивые ≥30 FPS в близком и общем высоком виде этого стенда, без визуальных регрессий; после первых двух итераций добавлять следующие измеренные шаги, если критерий не достигнут. Это критерий на проверочном устройстве, не обещание одинакового FPS на всех устройствах.

## Общие ограничения

- Сохранять совместимость сохранений, личности жителей, маршруты и учёт грузов.
- Не заменять присланные модели людей и не упрощать их одежду/руки вблизи.
- Не менять количество, материалы, положения, нормали и ориентацию растений.
- FPS измерять браузером; CPU указывать отдельно. Один seed, 200 жителей/129 зданий, 4×, 1280×720/DPR 1, 3 секунды прогрева + 12 секунд измерения; близкая и дальняя камеры, повтор исходной версии.
- Сравнивать только при отсутствии других 3D-вкладок и тяжёлых тестов. Ухудшивший результат эксперимент не публиковать без исправления.
- Исторических нововведений нет: сохраняются принятый облик Шумера и ранее обозначенные художественные условности.
- Журнал и отчёт обновлять коротко; посторонние материалы пользователя не включать в выпуск.

## Риски для проверки

1. Износ одежды меняется каждый тик: ключ только по порогам 50/25; настроение обновляется каждый кадр.
2. Здание может изменить тип с прежним ID; загрузка — заменить весь город с прежними ID жителей.
3. Похороны/профессия/вдохновение меняют одежду; груз и реликвия не должны зависеть от кэша внешности.
4. У тростника несколько материалов; тонкие экземпляры требуют правильных границ пакета, положительных матриц и независимых буферов геометрии.
5. Перестройка дорог/домов, смена качества и удаление сцены должны удалять старые растения без утечек и дубликатов.

В обоих сравнениях один seed, 200 жителей, 129 зданий, 62 поля, 900 шагов на 4×; первые 180 шагов прогревочные. Девять одинаковых переходов `field.crop` приходятся на восемь кадров. Используется настоящая статическая геометрия GLB и Babylon NullEngine; изображения заменены текстурами 1×1. Вызова `scene.render` нет: результаты показывают только CPU подготовки зданий, **не FPS или скорость GPU**.
